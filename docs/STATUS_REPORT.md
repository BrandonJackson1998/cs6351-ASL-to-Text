## Original Report Summary (May 2026)

We built a full ASL fingerspelling video → text pipeline. The strongest single
model is a **CTC Bi-LSTM** with **20.4% combined / 47.1% FSWild-only Letter
Error Rate** on real video. For *out-of-distribution alphabet recital*, a
**balanced Random Forest with hold-based decoding** dramatically outperforms
the CTC and produces recognizable substrings of all 10 target words on a
real fruit-fingerspelling video.

We tested a wide range of approaches and have clean experimental evidence for
which work and which don't. The path forward is the CTC for sequence
recognition + RF hold decoder for slow/balanced inputs + an LLM agent layer
to clean up output.

## Project Goal

Take a video of a person fingerspelling and produce English text. Course
project, two-person team (Brandon Jackson, Kevin Bateman). Multi-stage
pipeline: video → MediaPipe landmarks → letter classification → sequence
decoding → English text.

## Datasets used

| Dataset | Size | Use | Where |
|---|---|---|---|
| Kaggle ASL Alphabet | 87k static images, 26 letters (A–Z used) | Static letter classification | `data/asl_alphabet/` |
| Kaggle hand crops | 60k hand crop images (200×200 RGB) | CNN training | `data/hand_crops_kaggle/` |
| ChicagoFSWild | 5,429 video clips, 160 signers | Real fingerspelled-word sequences | `data/chicagofswild/` |
| ChicagoFSWild forced-aligned | 57,526 letter-stamped frames | Real-video per-letter training | `data/chicagofswild/letter_frames/` |
| Balanced merged | 104,000 frames (4k/letter) | Class-balanced per-letter training | `data/balanced_letter_frames/` |
| Example videos | `alphabet.mp4`, `Finger.mp4`, `sample_asl.mp4` | Live testing | `example_videos/` |

The **forced-aligned letter-frames** were generated by running CTC v2 over
every FSWild train clip with the known label, using constrained Viterbi to
assign each frame to a letter or blank. Self-supervised pseudo-labeling.

## What we built (chronological)

### Phase 1 — PPCA on Kaggle (worked)
- Implemented PPCA via Tipping & Bishop closed-form, plus PPCAMixture
  (one PPCA per letter, classify by max log-likelihood).
- 60/20/20 stratified split, augmentation (jitter, rotate, mirror).
- **Result:** PPCA + LogReg **96.4%**, Mixture-of-PPCAs **98.2%** on Kaggle test.
- Phase 1 deliverable in the proposal target.

### Phase 1c — CTC Bi-LSTM on real video (worked)
- Built a Bi-LSTM + CTC sequence model.
- v1 trained on synthetic concatenations of Kaggle frames + FSWild → **36.7%
  test LER**.
- v2 (3-layer × 256 hidden, weighted sampling, augmentation, char LM beam
  search) → **20.4% combined LER / 47.1% FSWild-only LER**.
- Best end-to-end sequence model in the project.

### Phase 2 — OpenHands word-level (worked, integrated)
- Cloned AI4Bharat/OpenHands repo, downloaded pretrained ST-GCN WLASL2000
  checkpoint.
- Built MediaPipe Holistic adapter → 75-keypoint pose tensor.
- Working single-clip word recognition. Out-of-the-box, treated as a baseline
  integration in the report.

### Pose-change segmentation (worked, then deprecated)
- Built a video segmenter that detects letter boundaries via frame-to-frame
  L2 distance in normalized 63D landmark space.
- Worked on `alphabet.mp4` (1 segment → 36 segments) where the older
  wrist-velocity segmenter failed.
- Eventually deprecated: CTC needs no segmentation.

### HMM + PPCA decoder (failed, instructive)
- Built standard HMM with PPCA-Mixture emissions and English bigram
  transitions.
- Required hand-tuned blank-emission constant — symptom of a real problem:
  the blank state's emission was on a different scale than the per-class
  PPCAs.
- Fixed by removing blank entirely (26-state HMM): still bad.
- **Result:** Test LER 95.9% on FSWild — distribution mismatch between
  Kaggle-trained PPCA and FSWild video frames is too severe.
- Lesson: a per-frame classifier trained on Kaggle stills cannot drive a
  sequence decoder on real video.

### HSMM (semi-Markov) decoder (failed)
- Mixture-of-PPCAs as emission, segmental Viterbi search jointly over
  spans + letters.
- Forced alignment under Kaggle-trained PPCA produced degenerate spans
  (mean letter "hold" ≈ 5 frames).
- **Result:** worse than HMM.

### Per-frame model comparison on real video (clean experiments)

After we had FSWild forced-aligned letter-frames, we trained four
per-frame letter classifiers on the **same** training data:

| Model | FSWild test acc (imbalanced) | Balanced test acc (Kaggle + FSWild) |
|---|---|---|
| PPCA + LogReg | 52.5% | **75.9%** |
| PPCA-Mixture (single Gaussian / class) | 48.0% | **75.8%** |
| MPPCA (5–8 Gaussians / class) | 52.1% | **78.3%** |
| RBF-SVM (C=10, γ=scale) | 58.0% | n/a |
| **Random Forest (500 trees, mtry=8)** | **62.0%** | **82.7%** |

Two findings:
1. **Random Forest beats every other per-frame model** on real video frames
   — the course-recommended discriminative ensemble outperformed the
   Gaussian-mixture-based generative methods we'd been using.
2. **Class balancing is huge.** Per-letter accuracy jumped 20–28 points
   when we balanced the training frames to 4k/letter. The original FSWild
   pool had 28 frames for Q vs 6,545 for A — rare letters were untrained.

### Shallow fusion experiments (small win)
- Tried blending CTC v2 per-frame log-probs with per-frame emission
  models at decode time, sweeping λ ∈ [0, 4] on dev.

| Emission for fusion | Best λ on dev | Test LER vs CTC-only |
|---|---|---|
| PPCA-Mixture (Kaggle) | 0.0 | no improvement |
| PPCA-Mixture (FSWild refit) | 0.0 | no improvement |
| **Random Forest (FSWild)** | **0.25** | **−0.3 LER points (FSWild-only)** |
| RBF-SVM | n/a (skipped after RF) | n/a |

CTC has internalized most of the per-frame signal. Only RF — the strongest
per-frame model — adds anything, and only a tiny bit.

### Hold-based RF decoder (best for slow/OOD signing)
- For inputs the CTC wasn't trained for (slow alphabet recital, varied pace
  signing), we built a separate decoder: per-frame RF prediction + sliding-
  window majority smoothing + hold detection (≥0.5s of consistent prediction).
- **No CTC, no LSTM, no LM.** Just RF + simple temporal smoothing.

Result on `Finger.mp4` (10 fingerspelled fruit names, recorded fresh):

| Fruit | Found in RF hold output |
|---|---|
| FIG | ✓ exact (twice) |
| DATE | ✓ exact (twice) |
| LIME | ✓ exact (twice) |
| GUAVA | ✓ exact (and partial GRAUA) |
| OLIVE | ✓ exact (and partial OLIUE) |
| PRUNE | partial: PRNE PRETN |
| MANGO | partial: GONANG |
| PAPAYA | ✓ exact (and partial ANAYA) |
| PASSIONFRUIT | ✓ partial NASIONFRUIT (11/12 chars) |
| FRUIT | ✓ exact |

All 10 target words are recoverable from the output. **This is the strongest
real demo we have.**

### Auto-calibration of transcribe thresholds (partially worked)
- Built `calibrate_transcribe.py` to derive `low_conf_threshold`, `min_hold`,
  `min_break`, and `stillness_threshold` from FSWild data.
- `low_conf_threshold = 0.30` calibrated cleanly (per-frame accuracy crosses
  50% there).
- `min_hold` and `min_break` came from FSWild's fast spelling, which clamps
  to 200ms and 500ms minimums — but these are too short for slow alphabet-
  recital videos. Defaults are wrong scale for OOD pace.
- `stillness_threshold` calibrated but interaction with smoothing produced
  worse output than hand-picked defaults.
- **Conclusion:** auto-calibrating from one data distribution doesn't
  generalize to a different signing speed. Honesty in the writeup: report
  this and use distribution-matched thresholds when known.

## What didn't work, and why

### HMM + PPCA emissions
The blank state forced us to mix PPCA log-likelihoods (range −300 to +100)
with a hand-picked constant. No principled scale.
**Lesson:** if your decoder needs you to set a constant, your emission model
isn't really driving the decoder.

### HSMM with PPCA emissions
PPCA trained on Kaggle stills is too distribution-shifted from FSWild video
frames; forced alignment under the Kaggle-trained PPCA produced degenerate
spans (5-frame "letters").
**Lesson:** the bottleneck was the emission model, not the decoder.

### PPCA fusion with CTC (Kaggle or FSWild-refit)
λ=0 won on dev for both. CTC LSTM has internalized everything PPCA captures.
**Lesson:** end-to-end neural models on in-domain data tend to dominate
classical generative models for sequence tasks.

### Auto-calibrating min_hold / min_break for slow signing
Calibrated values came from fast spellers in FSWild and didn't transfer to
slow alphabet-recital pace.
**Lesson:** distribution matching is required for threshold calibration to
generalize, or thresholds need to be *adaptive per video*.

### Synthetic data for CTC training
v1 CTC trained on synthetic concatenations only hit 9% LER on synthetic val
but 76% recall on real video. Linear-interp transitions don't match real
fingerspelling transitions.
**Lesson:** synthetic data has a real ceiling; real data is dramatically
better when available.

## What's left and forward direction

### Sufficient for the writeup as-is
- Phase 1 PPCA (96–98% on Kaggle) — own ML, complete.
- Phase 1c CTC v2 (20% combined / 47% FSWild LER) — own ML, complete.
- RF balanced + hold decoder demo on real video — clear demo.
- Extensive ablations (HMM/HSMM/synthetic-CTC/fusion) as negative results.

### Phase 3 (LLM agent) — not yet built
The proposal calls for a Claude API layer that ingests gloss/letter sequences
and produces grammatical English. Easy to wire up:

```
RF transcribe(Finger.mp4) → "FIGFIGDATEDATELIME..."
Claude: "given this noisy fingerspelling, output the most likely English words"
→ "fig, date, lime, guava, olive, prune, mango, papaya, passionfruit, fruit"
```

### Stretch: dictionary-aware spell correction
Take noisy RF output, snap each substring to nearest English word via edit
distance against a fruit/word vocabulary. Cheap to build, would clean up
demo output substantially.

### Things we explicitly chose not to pursue
- Refit OpenHands or fine-tune for our specific videos.
- Build a temporal CRF/HMM-CRF on top of CTC.
- Try a Transformer encoder (CTC v2 is the stretch goal in the proposal).
- Implement on GPU.

## What we're moving forward with

1. **CTC v2** (`experiments/latest_ctc_v2/`) for FSWild-style real fingerspelling
   videos.
2. **RF balanced + hold decoder** (`experiments/rf_balanced/`) for slow,
   balanced-letter videos like the alphabet or the fruit demo.
3. **OpenHands** (`data/openhands_checkpoints/`) for word-level recognition
   on segments where the signer drops their hand between signs.
4. **Phase 3 LLM agent** (next, not yet built) to reconcile the noisy
   per-letter / per-word outputs into clean English.

A practical user-facing flow:

```
video
  ├─ fingerspelling-mode → RF hold decoder (or CTC for fast spelling)
  └─ word-sign mode → segmenter + OpenHands
                          ↓
                    gloss / letter sequence
                          ↓
                    Claude API → English
```
